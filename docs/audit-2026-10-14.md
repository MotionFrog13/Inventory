# Tinjauan fitur dan keamanan — 14 Oktober 2026

Tinjauan kode, dependensi, dan pengujian lokal. Fokus: autentikasi, pemisahan organisasi/divisi/outlet, transaksi stok, BAP, transfer, dan perubahan peran. Implementasi berada di working tree; belum dipublikasikan.

## Perbaikan yang dikerjakan

| Masalah | Perubahan dan bukti |
| --- | --- |
| API bergantung pada header identitas dari proxy | API memverifikasi cookie JWT sendiri. Header palsu tanpa cookie ditolak. Peran dan penugasan tetap dimuat dari database setiap request. |
| JWT dengan identitas tidak lengkap masih diterima | Verifikasi menolak field kosong/salah tipe, peran lama, serta algoritme selain HS256. Token dengan `userId` hilang tidak bisa masuk ke query pengguna. |
| Request perubahan belum memeriksa origin | Proxy menolak origin berbeda, termasuk subdomain lain, untuk mutasi API dan login/logout. Klien API tanpa header browser tetap didukung. Host asli diteruskan untuk deployment Docker/Cloudflare. |
| Login belum dibatasi | Maksimal 10 percobaan per identifier/15 menit dan 120 percobaan seluruhnya/menit per proses; penolakan 429 disertai `Retry-After`. Kode organisasi tidak memengaruhi bucket username pada mode self-hosted, dan tidak memengaruhi bucket email. |
| Perubahan stok bisa menimpa snapshot lama | Penulisan stok memeriksa versi, seluruh bucket, status, divisi, dan outlet sebelumnya. Konflik membatalkan transaksi dan menghasilkan 409; BAP/insiden tidak ikut tersimpan bila stok gagal diperbarui. |
| Transfer lama dapat disetujui setelah aset pindah/terkunci | Persetujuan memeriksa outlet asal dan kondisi aset saat ini, serta menjaga snapshot saat memindahkan aset. |
| Pengajuan transfer bersamaan menghasilkan beberapa PENDING | Pemeriksaan dan create dipindah ke transaksi serializable. Sebelum perbaikan: 8 request menghasilkan 5 PENDING; setelah perbaikan hanya 1 diterima. |
| Dua demosi bisa menghilangkan seluruh Super Admin | Count dan perubahan/hapus akun dilakukan dalam transaksi serializable. Sebelum perbaikan: kedua demosi berhasil dan admin tersisa 0; setelah perbaikan salah satu ditolak dan admin tersisa 1. |
| Konflik saat commit PostgreSQL menjadi 500 | Penanganan mencakup P2034 maupun `DriverAdapterError` untuk konflik serialisasi/deadlock; respons menjadi 409. |
| MIME unggahan berasal dari klien | PDF diperiksa signature/EOF; gambar harus terdeteksi sebagai JPEG, PNG, atau WebP, diberi batas pixel, dirotasi sesuai orientasi, lalu dikompres WebP kualitas 75 maksimal 1920px. SVG dengan MIME PNG ditolak. |
| Batas file diperiksa setelah multipart dibaca penuh | Keseluruhan multipart dibatasi 6MB sebelum parsing, termasuk tanpa Content-Length. Batas masing-masing file tetap 5MB. Field teks dan berkas kosong divalidasi. |
| Kuantitas pecahan atau teks seperti `2pcs` dipotong menjadi integer | API menolak pecahan, suffix, boolean, dan angka di luar rentang integer PostgreSQL. |
| Nama Unicode menyebabkan error header HTTP | Header identitas yang tidak lagi digunakan dihapus dari output proxy; sanitasi header masuk tetap ada. |
| Halaman log mengandalkan peran lama dalam JWT | Pemeriksaan memakai peran database; halaman server juga memiliki guard sendiri. |
| Advisory dependensi | Next.js dan konfigurasi ESLint diperbarui ke 16.4.0, sharp ke 0.35.5, dan patch kompatibel dari `npm audit fix` diterapkan. Total audit turun dari 24 (termasuk 1 critical) menjadi 9 high. |

## Verifikasi

- `npm run typecheck`: lulus.
- `npm run lint`: tanpa error; dua peringatan `<img>` yang sudah ada di LoginForm dan Sidebar.
- `npm run build`: lulus. Tracing unggahan runtime diperbaiki agar tidak menyertakan seluruh proyek.
- `npm run test:unit`: 33/33 lulus.
- `npm run test:integration`: 13/13 lulus, termasuk penulisan stok bersamaan dan rollback transaksi.
- `npm run qa` setelah reseed: 62/62 lulus (54 skenario bisnis dan 8 skenario keamanan).
- Reseed dan QA menggunakan `APP_MODE=saas`, server lokal port 3100, database QA baru, dan direktori unggahan sementara. Data database inventaris asli tidak di-reseed.
- Review independen dilakukan dua kali. Temuan Unicode dan bypass bucket self-hosted ditindaklanjuti.

Tidak ada perubahan schema, migrasi, startup Docker, atau mekanisme seed. Docker dev/prod tidak dibangun ulang dalam tinjauan ini.

## Pekerjaan keamanan lanjutan

1. **Sisa advisory dependensi:** `braces` dan rantai ESLint/fast-glob/micromatch; `deepmerge-ts`, `@prisma/config`, `mysql2`, dan Prisma CLI. Terdapat 9 entri high pada audit terakhir, termasuk 4 entri pada `npm audit --omit=dev` karena Prisma CLI juga terpasang melalui dependensi/peer. Docker produksi membawa alat tersebut untuk migrasi/seed. Aplikasi menggunakan PostgreSQL, sehingga jalur protokol MySQL tidak dipakai aplikasi, tetapi paketnya tetap perlu dipantau. `npm audit fix --force` menawarkan downgrade ke Next ESLint 14/Prisma 6; perubahan itu tidak diterapkan karena tidak sesuai arsitektur saat ini. Upgrade major/override perlu pengujian kompatibilitas terpisah.
2. **Rate limiting produksi:** counter lokal hilang saat restart dan tidak dibagi antarreplika. Email dan username memiliki counter terpisah. Untuk trafik publik, tambahkan limit IP di edge atau penyimpanan counter bersama sesuai konfigurasi deployment.
3. **Sesi:** belum ada pencabutan token aktif saat password berubah, MFA, reset password, atau verifikasi email. Perubahan peran/penugasan sudah langsung berlaku karena dibaca dari database.
4. **Dokumen PDF:** signature/EOF merupakan pemeriksaan dasar, bukan parser lengkap, optimizer, antivirus, atau content disarm/reconstruction. Pemrosesan struktural dan sanitasi PDF masih perlu ditambahkan sebelum menerima dokumen dari pihak yang tidak dipercaya.
5. **Backup:** panduan backup Docker sudah tersedia. Otomatisasi backup database dan unggahan, retensi, serta uji restore berkala akan melengkapi pemulihan operasional.
